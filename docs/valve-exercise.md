# Тренировка клапанов по группам защиты

Одна запись **Home Control → Тренировка клапанов** описывает одну группу защиты:
список клапанов и относящиеся к ней датчики протечки. Можно создавать несколько
групп и добавлять клапаны через параметры записи. Один клапан не может принадлежать
двум процессам Home Control. Количество клапанов в группе не фиксировано.

Процесс рассчитан на существующие сущности с аппаратной обратной связью:
`switch off` — клапан полностью открыт, `switch on` — полностью закрыт.
Это именно подтверждённое положение, а не состояние управляющего реле.
Датчик протечки должен иметь `on` при наличии воды, `off` при её отсутствии.

Home Control не изменяет Modbus Devices, программы Bolid или их конфигурацию.
Аварийное закрытие выполняется Bolid. Тренировка не является системой защиты от протечек.

## Настройка

1. Обновите интеграцию, перезапустите HA, обновите страницу интерфейса.
2. Добавьте Home Control → **Тренировка клапанов**.
3. Назовите группу по помещению. Выберите её клапаны горячей и холодной воды
   и датчики протечки. Список датчиков обязателен.
4. Укажите число месяца и время тренировки, интервал повторной проверки.
5. При необходимости измените тайм-аут движения, выдержку и паузу между клапанами.
6. После проверки выбранных сущностей включите **Автоматика**.

Каждая запись создаёт:

- выключатель **Автоматика**, по умолчанию выключенный, с сохранением состояния;
- кнопку **Запустить тренировку** — соблюдает те же проверки, повторяет цикл для
  всех клапанов группы, включая исправные, и разрешает ручную повторную попытку
  после ошибки или прерывания;
- `binary_sensor` **Протечка группы**.

Два помещения с двумя стояками воды на каждое настраиваются двумя записями,
по два клапана в каждой. Дальнейшие группы, например отопление, добавляются так же.

## Состояния защиты

| Датчики группы | Протечка группы | Тренировка |
| --- | --- | --- |
| Хотя бы один `on` | `on` | Запрещена |
| Все `off` | `off` | Разрешена при открытом клапане |
| Никто не сообщает протечку, но есть неизвестный/недоступный | `unknown` | Запрещена |

Сенсор группы обновляется по событиям Home Assistant и при запуске интеграции.
Он работает также при выключенной тренировке. Это обработка уже поступивших
данных, без запросов к оборудованию.

Для цикла используются выборки состояний HA перед стартом и перед обратным
открытием. При закрытом клапане сначала откладывается его тренировка, без выборки
датчиков. Циклического опроса датчиков, `update_entity` и Modbus-запросов нет.
Актуальность исходных состояний обеспечивает интеграция оборудования.

## Очередь и календарь

По умолчанию календарь — 1-го числа в 03:00 по часовому поясу HA. Для числа 29–31
в коротком месяце используется его последний день. Интервал переноса по умолчанию
1 час, настраивается отдельно. Планировщик проверяет срок раз в минуту; фактический
старт может быть позже из-за занятой общей очереди.

У каждого клапана отдельно сохраняются исходный плановый срок `due`, время
следующей проверки `retry_at`, результат и дата успешного завершения `last_success`.
Закрытый или недоступный клапан остаётся `pending`. При следующей попытке сначала
проверяется его положение, затем защита группы. После успеха он исключается из очереди.

Позднее выполнение не сдвигает месячное расписание. Если наступил новый месяц,
а прошлый цикл всё ещё ожидает, остаётся один незавершённый цикл с первоначальным
сроком, без накопления повторов. Следующая календарная дата рассчитывается по
настройкам. Ручной запуск также не сдвигает календарь.

Перезапуск сохраняет очередь. Планировщик начинает проверку через минуту после
загрузки; немедленных команд при старте нет. Пропущенные сроки объединяются в одну
тренировку. При изменении числа, времени или часового пояса следующая календарная
дата пересчитывается; уже ожидающие клапаны сохраняют исходный срок. Новый интервал
переноса применяется при следующем откладывании.

## Цикл и прерывания

Все группы используют общую очередь: одновременно тренируется один клапан.
Повторное нажатие кнопки во время обработки своей группы игнорируется.

1. Только подтверждённое открытое положение и сухая группа разрешают старт.
2. Закрытие: `switch.turn_on`; ожидание подтверждённого `on` до тайм-аута.
3. Выдержка в закрытом положении.
4. Повторная проверка защиты и закрытого положения.
5. Открытие: `switch.turn_off`; ожидание подтверждённого `off`.

Ожидание движения проверяет состояние клапана в памяти HA с монотонным тайм-аутом.
Оно не запрашивает оборудование. Во время движения прежнее конечное состояние
допустимо до истечения тайм-аута. Недоступность клапана, неожиданная смена положения
во время выдержки или сигнал неисправной защиты прерывают цикл без последующих
команд этому клапану. Протечка или неизвестность защиты, замеченные во время цикла,
фиксируются как причина прерывания, даже если состояние затем восстановилось.

Ошибка движения (`failed`) и прерванный цикл (`interrupted`) требуют ручного запуска
после проверки оборудования, а не автоматических повторов каждый час. Ошибка
одного клапана не препятствует проверке остальных, если защита группы разрешает её.
После перезапуска незавершённый этап движения превращается в `interrupted`.
Самостоятельного восстановления открытого положения нет.

Отключение автоматики запрещает новые команды и аннулирует ожидающие действия.
Уже отправленная команда не отзывается. Поэтому клапан может остаться закрытым;
автоматика не откроет его при выключении или следующем запуске. Очередь сохраняется.

Состояния и ошибки каждого клапана, активный этап и следующая плановая дата доступны
в атрибутах выключателя **Автоматика**. `pending` означает отложенную попытку,
`completed` — полный подтверждённый цикл, `failed` — ошибку, `interrupted` — прерывание.
При ошибке записи хранилища новые циклы блокируются до восстановления и повторного
включения автоматики.

Проверка датчиков в HA не является аппаратной блокировкой команды открытия.
Событие аварии может поступить с задержкой или одновременно с отправкой команды;
приоритет аварийного управления в оборудовании остаётся ответственностью Bolid.
