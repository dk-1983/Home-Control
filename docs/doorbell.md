# Дверной звонок на Яндекс Станциях

С версии 0.8.0 процесс **Дверной звонок** воспроизводит один MP3 на выбранных
колонках через установленную интеграцию Yandex.Station. Нужен локальный режим
Станций и доступ колонок к HTTP(S)-адресу файла. Используется `stream.mp3`.
Music Assistant и отдельный helper для первых тестов не требуются.

## Настройка

1. Обновите Home Control и перезапустите Home Assistant.
2. Добавьте запись Home Control → **Дверной звонок**.
3. Выберите одну колонку для первого теста. Позднее можно выбрать несколько.
4. Укажите доступную по сети ссылку на MP3. Файлу `/config/www/sound/bell.mp3`
   соответствует `http://<адрес HA>:8123/local/sound/bell.mp3`.
5. Установите дневную громкость от 0 до 1, длительность звука и паузу между
   звонками. Длительность по умолчанию 10 секунд — это время до возврата
   громкости после отправки команды; оно не обрезает файл. Учитывайте задержку
   начала воспроизведения и задайте длительность не меньше времени звучания.
6. Для теста выберите источник **Только виртуальная кнопка**. Поля остальных
   источников можно оставить пустыми; активное состояние относится только к датчику.
7. Настройте интервалы и нажмите **Сохранить**. По умолчанию ежедневно
   действует тишина с 23:00 до 09:00.
8. Включите **Автоматика**, затем нажмите созданную кнопку **Позвонить**.
   Она соблюдает ночные ограничения. Для ночного теста настройте звуковой
   интервал только с колонкой рядом с вами.

Для изменения интервала удалите его и добавьте новый перед сохранением.
Для каждого интервала задаются дни начала, время, режим тишины или звука,
список колонок и громкость. Например, пятница 23:00–09:00 заканчивается в
субботу. Начало включительно, конец исключительно. Используется часовой пояс HA,
точность — минуты. Пересечения, в том числе через границу недели, запрещены.
Вне интервалов действуют дневные настройки. Пустой список означает отсутствие
тихих интервалов.

## Физический источник

- `binary_sensor`: событие перехода из известного противоположного состояния
  в выбранное `on` или `off`. Появление сущности и восстановление из
  `unknown`/`unavailable` не запускают звонок.
- `input_button`: изменение состояния при нажатии существующего helper.
- MQTT: точный топик, значение нажатия и необязательный путь к полю JSON.
  Например, ключ `Switch1`, значение `OFF`, либо `Button1.Action` и `SINGLE`.
  Пустой ключ сравнивает payload целиком. Retained и неподходящие сообщения игнорируются.
  Выбирайте сообщения события нажатия: повторная периодическая телеметрия
  с тем же значением после окончания паузы также считается новым событием.

Встроенная кнопка доступна при любом выбранном источнике. Никаких изменений
прошивки контроллера процесс не выполняет.

## Громкость и ограничения

Перед сигналом сохраняется известная громкость каждой колонки, затем задаётся
громкость текущего интервала. Колонка с неизвестным `volume_level` пропускается.
Возврат выполняется по таймеру только если громкость всё ещё соответствует
установленной процессом: ручное изменение на другое значение сохраняется.
Равное значение не позволяет определить, менял ли громкость пользователь.

Автоматическое возобновление музыки не реализовано. Воспроизведение файла может
прервать текущую музыку; поведение нужно проверить на конкретной Станции.
Команды отправляются параллельно, но синхронное начало звука не гарантируется.
Состояние `sent` означает успешные вызовы сервисов, а не акустическое подтверждение.
Ошибки возврата громкости записываются в журнал HA.

Пока обрабатывается предыдущий звонок или не закончилась пауза, новые нажатия
отбрасываются без очереди. Ошибка одной колонки не мешает остальным.
Выключатель автоматики сохраняется между перезапусками. Новая запись выключена.
Отключение автоматики запрещает дальнейшие команды, включая возврат громкости;
уже начавшийся звук не останавливается. Перезапуск не воспроизводит звонок.
