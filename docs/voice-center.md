# Центр голосовых оповещений

Один центр Home Control обслуживает процессы квартиры. Для речи используется установленная интеграция [YandexStation](https://github.com/AlexxIT/YandexStation): `media_player.play_media`, тип `text`, временная громкость через `extra.volume_level`.

## Первый запуск

1. Обновить Home Control, перезапустить Home Assistant и обновить страницу браузера.
2. В Home Control нажать «Добавить службу» и выбрать **«Центр голосовых оповещений»**.
3. Настроить громкость INFO, WARNING, ERROR, интервал повторов и при необходимости резервное помещение INFO.
4. Добавить помещения и их Яндекс Станции. Помещение без колонки тоже можно добавить: например, прихожую с альтернативами «Кухня» и «Зал».
5. При необходимости выбрать датчики присутствия и движения для альтернативных помещений. Порядок альтернатив определяет приоритет.
6. Настроить ночные интервалы и сохранить. Новый центр содержит тишину **23:00–09:00 ежедневно**. Чтобы изменить этот интервал, сначала удалить его, затем добавить новый.
7. Включить переключатель **«Автоматика»** центра. Кнопка **«Проверка оповещения»** отправляет тест на все колонки центра с учётом ночных правил.
8. Открыть настройки нужного процесса Home Control, выбрать помещение и включить необходимые уровни оповещения. По умолчанию INFO, WARNING, ERROR и повторы выключены.

Для первого теста достаточно добавить одну колонку. Центр требует локального подключения Яндекс Станции: в её состоянии должен присутствовать атрибут `alice_state`. Облачный режим не используется, поскольку временная громкость TTS в YandexStation поддерживается локально. При потере локального подключения колонка исключается из маршрута.

Помещение процесса можно задать полем «Помещение оповещений». Если оно пустое, используется помещение устройства **самого процесса Home Control** в HA. Центр не ищет комнату по аппаратным реле. При замене реле или контроллера меняются поля существующего процесса; его связь с центром сохраняется. Удаление процесса и создание нового создаёт новый идентификатор.

## Маршруты

| Уровень | Куда направляется |
| --- | --- |
| INFO | Все доступные колонки помещения события |
| INFO без доступной локальной колонки | Первая настроенная альтернатива с присутствием и доступной колонкой |
| INFO без подходящей альтернативы | Резервное помещение, если настроено |
| WARNING, ERROR | Все настроенные доступные колонки центра без дублирования |

Если подходящего маршрута нет, центр отмечает `silent_or_no_route`; сообщение не откладывается до появления человека. Присутствие определяется состоянием `on` выбранного датчика. Для движения дополнительно учитывается настраиваемое время после последнего наблюдавшегося `on`; `unknown` и `unavailable` не считаются присутствием. При перезапуске история движения не восстанавливается. Принудительных опросов оборудования нет.

## Ночь и напоминания

Ночные интервалы задаются по времени HA и дням недели. День относится к началу интервала, поэтому понедельник 23:00–09:00 заканчивается во вторник. Интервалы не пересекаются; точность — целая минута.

- **Тишина** запрещает голос всех уровней, включая ERROR.
- **Звук** задаёт громкость и необязательный список колонок. Пустой список означает все колонки, подходящие по маршруту. Ограниченный список пересекается с маршрутом; INFO не превращается в общедомовое сообщение.
- Сообщения, пропущенные во время тишины, утром не воспроизводятся пачкой.
- Только активные ERROR могут повторяться с заданным интервалом. У процесса должны быть включены ERROR и «Повторять активные ERROR».
- После окончания тихого интервала может прозвучать очередное напоминание об **остающейся активной** ошибке. Устранённая ошибка больше не повторяется.

Активность ошибки сообщает исходный процесс. Например, его `last_error` может оставаться до успешной следующей операции или сброса неисправности. Центр не считает самостоятельное изменение положения оборудования доказательством устранения такой ошибки. Напоминания отключаются отдельно для каждого процесса.

## Какие события подключены

- Освещение кнопкой: изменение установившейся комбинации основных групп и ошибки процесса. Переключение отдельного ночника пока не озвучивается.
- Освещение по движению, общая вентиляция, вентиляция по влажности: изменение состояния выхода и ошибки; недостаточные данные влажности — WARNING.
- Кухонная вытяжка: установившаяся скорость или остановка, ошибки управления, входов и подсветки. Промежуточное отключение при смене скорости не озвучивается как остановка.
- Тренировка клапанов: успешное завершение каждого клапана — INFO, отложенная тренировка — WARNING, ошибка/прерывание — ERROR.
- Звонок: ошибка последней попытки подачи сигнала — ERROR. Дополнительной речи после успешного звонка нет.

INFO отражает доступное состояние HA после короткого ожидания установления, а не гарантирует физическое положение любого исполнительного устройства. Формулировки первой версии русские; название процесса добавляется к сообщению. Сам центр не управляет реле, вентиляторами или клапанами.

## Очередь и дверной звонок

Очередь отдельная для каждой колонки: ошибка одной не задерживает остальные. Среди ожидающих сообщений приоритет ERROR → WARNING → INFO. Уже отправленная речь не прерывается. На колонке хранится максимум 32 ожидающих сообщения; при переполнении удаляется старое сообщение меньшего приоритета.

Срок актуальности ожидающего INFO — 30 секунд, WARNING — 60, ERROR — 120. Новое сообщение с тем же ключом заменяет ожидающее старое. Одинаковые события подавляются в течение 10 секунд. Перед воспроизведением повторно проверяются источник, активность ошибки, маршрут и ночные ограничения.

Звонок использует тот же доступ к колонке. Свободные колонки звонят сразу, занятые ожидают не более **15 секунд**. Просроченный звонок на занятой колонке пропускается и отражается в диагностике звонка как неудачная доставка. Глобальной блокировки звонка нет.

Сервис воспроизведения подтверждает приём команды, а не фактическое окончание звука. Центр выдерживает паузу — максимум заданного минимума и оценки по длине текста — и дополнительно учитывает публичное состояние `alice_state`. Зависшее состояние речи ограничено тайм-аутом. Для MP3 используется настроенная продолжительность звука звонка; её нужно выставить не короче записи. Эти ограничения стоит проверить на реальных колонках.

Выключение автоматики центра очищает ожидающие сообщения и прекращает новые команды. Уже переданная колонке речь может закончиться самостоятельно; команда остановки не отправляется. Выключение процесса отменяет его ожидающие сообщения и напоминания. Громкостью TTS и её восстановлением занимается YandexStation. Очереди не восстанавливаются после перезапуска; текущие ошибки заново поступают от загруженных процессов.

## Обмен событиями

Встроенные процессы подключены автоматически. Дополнительный сценарий может использовать действие `home_control.announce`. В поле «Процесс Home Control» выбирается существующий загруженный процесс — это устойчивый идентификатор записи конфигурации, а не сущность реле.

```yaml
action: home_control.announce
data:
  source: "CONFIG_ENTRY_ID_ПРОЦЕССА"
  key: "water_pressure"
  level: ERROR
  message: "Не удалось восстановить давление воды."
  active: true
```

Снятие проблемы:

```yaml
action: home_control.announce
data:
  source: "CONFIG_ENTRY_ID_ПРОЦЕССА"
  key: "water_pressure"
  resolved: true
```

Без `active: true` сообщение одноразовое. Допустимы INFO, WARNING, ERROR; текст до 500 символов. Настройки уровней и включённость выбранного процесса действуют и для этого действия. Внешний сценарий обязан сообщить `resolved: true`, когда проблема устранена. События через действие используют отдельное пространство ключей и не снимают встроенные ошибки процесса.

Атрибуты переключателя центра показывают результат последней операции, число ожидающих сообщений и активных проблем, источник последнего сообщения и результаты по колонкам. `submitted` означает, что команда передана сервису; это не аппаратное подтверждение слышимости. При отсутствии звука сначала проверить ночной интервал, переключатели центра/процесса, выбранный уровень, помещение и локальное подключение колонки.
