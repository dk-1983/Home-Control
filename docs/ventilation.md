# Освещение по движению и вентиляция санузла

Реализованы независимые процессы. Алгоритм влажности находится в `humidity.py`, освещение по движению и общая вытяжка — в `environment.py`. Они используют общий адаптер Home Assistant, но имеют отдельные состояния, настройки и переключатели «Автоматика».

## Экземпляры процессов

Для ванной и туалета создаются четыре записи интеграции:

| Запись | Тип | Выход |
| --- | --- | --- |
| Свет ванной | Освещение по движению | Свет ванной |
| Свет туалета | Освещение по движению | Свет туалета |
| Общая вытяжка | Общая вытяжка | Общий вентилятор |
| Осушение ванной | Вентиляция по влажности | Вентилятор ванной |

Физический контроллер может обслуживать несколько помещений. Автоматика привязана к сущностям, а не к корпусу контроллера. Выход принадлежит только одному процессу; использовать его состояние как вход другого процесса разрешено.

## Освещение

Один или несколько датчиков движения включают свет по логическому «ИЛИ». Таймер выключения запускается только когда **все** датчики имеют состояние `off`. Новое движение отменяет таймер. `unknown`, `unavailable` и отсутствующий датчик не подтверждают отсутствие человека: таймер выключения сбрасывается.

Ручное включение света без движения получает полный таймер. По умолчанию задержка 600 секунд; для туалета можно задать 300. Изменения атрибутов без изменения состояния таймер не продлевают. При движении автоматика поддерживает свет включённым; для ручного управления без этого поведения отключите её переключатель.

## Общая вытяжка

Входы — список источников света и список вентиляторов, требующих общей вытяжки. В рассматриваемой схеме это свет ванной, свет туалета и вентилятор ванной.

- Если хотя бы один свет включён, начинается задержка запуска: по умолчанию 120 секунд. Смена активного помещения при непрерывно истинном общем условии её не перезапускает.
- Подтверждённое включение вентилятора ванной требует включить общий вентилятор без этой задержки. Обработка событий дополняется секундной проверкой текущего состояния.
- Пока хотя бы один источник активен, общий вентилятор не выключается.
- После подтверждённого выключения всех источников начинается выбег: по умолчанию 60 секунд.
- Неизвестное состояние любого источника блокирует выключение. Известный активный вентилятор разрешает включение даже при недоступном другом источнике.

Влажностный процесс **не отправляет команды общему реле**. В отличие от старого pyscript, включение общего вентилятора происходит по подтверждённому состоянию вентилятора ванной, а не перед отправкой ему команды. Это устраняет двух независимых владельцев общего реле. Общая вытяжка также восстановит своё включение, если её выключили во время работы вентилятора ванной и её автоматика включена.

## Решение о завершении осушения

Абсолютного порога влажности нет. Свет разрешает запуск при росте, но не запрещает штатное завершение уже начатого осушения.

1. При включённом свете подтверждённый рост запускает вентилятор ванной.
2. Уверенный рост и уверенное снижение продолжают вентиляцию независимо от общей длительности работы.
3. Кандидат на завершение — устойчивое плато: малый наклон и небольшой разброс последних измерений.
4. Выключение требует и нескольких последовательных стабильных окон, и заданной длительности плато. По умолчанию — минимум три окна и пять минут с начала подтверждённой стабильности. Это дополнительное время после классификации окна, а не пять минут от запуска вентилятора.
5. Рост, снижение, колебания вне диапазона стабильности или потеря данных сбрасывают подтверждение плато. При возобновлении снижения вентиляция продолжает осушение.

Пять перекрывающихся измерений не считаются пятью независимыми минутами подтверждения. Длительность плато проверяется отдельно, счётчик увеличивается только при новом сообщении датчика. Повторное чтение того же сообщения не добавляет измерение.

Плато — признак отсутствия измеримого дальнейшего снижения, а не доказательство физически минимальной возможной влажности. Значения по умолчанию требуют проверки на реальной динамике конкретной ванной. Влияют частота публикации датчика, шум и обновление воздуха.

## Страховка и данные датчика

Вместо прежних 90 минут после выключения света используется настраиваемое **время без понятного тренда при работающем вентиляторе**, по умолчанию 20 минут. Это не предел общей длительности вентиляции.

Отсчёт возможен только после наблюдения `on` у вентилятора. Если при запуске нет пригодного тренда, отсчёт начинается с этого момента. Рост или снижение сбрасывают его. Если полезное осушение сменилось длительным отсутствием данных или неопределёнными колебаниями, отсчитывается новый интервал. Краткие плато между колебаниями не обнуляют страховку; подтверждённое плато обрабатывается штатным завершением. Само выключение света отсчёт не запускает.

Страховка проверяется независимо от минутного анализа, в том числе при недоступном датчике. При `RISING` или `FALLING` она не выключает вентилятор. При устойчивом `STABLE` действует подтверждение плато.

Принимаются только конечные значения 0–100 %RH. `NaN`, бесконечность, недоступность и слишком старое сообщение сбрасывают историю. По умолчанию сообщение старше 600 секунд считается устаревшим. Возраст оценивается по `last_reported` в HA, а не по `last_changed`: неизменное значение может быть свежим. Это подтверждает поступление в HA, но не позволяет обнаружить датчик, который продолжает передавать неверное постоянное значение.

Регрессия использует времена сообщений, а не предполагает одинаковую минуту между всеми точками. После разрыва с недоступным датчиком окно набирается заново. Стартовая и периодическая проверки используют один планировщик.

## Параметры влажности

| Параметр | По умолчанию |
| --- | --- |
| Интервал анализа | 60 секунд |
| Размер окна / минимум измерений | 5 / 3 |
| Порог роста | +0,30 процентного пункта RH в минуту |
| Порог снижения | −0,20 процентного пункта RH в минуту |
| Допустимый модуль наклона плато | 0,12 процентного пункта RH в минуту |
| Допустимый разброс плато | 0,8 процентного пункта RH |
| Стабильных окон | 3 |
| Подтверждение плато | 300 секунд |
| Страховочное ожидание | 20 минут |
| Допустимый возраст сообщения | 600 секунд |
| Подтверждение команды реле | 5 секунд |

Все параметры доступны в настройках экземпляра. Размер окна не меньше минимума измерений; полоса плато не пересекает пороги роста/снижения. Частота публикации датчика задаётся на самом устройстве и здесь не меняется.

## Ручное управление, ошибки и перезапуск

После обнаруженного внешнего выключения влажностный процесс не включает вентилятор немедленно снова на том же продолжающемся росте. Для нового автоматического запуска нужны наблюдённое плато/снижение после выключения и новый рост. Явное внешнее включение принимается как новый рабочий цикл. После автоматического завершения действует такая же защита от повторного запуска на остаточном эпизоде.

При запуске интеграции есть пауза 5 секунд для появления состояний. Уже включённый вентилятор принимается через `ADOPTED`, но прошлый тренд не выдумывается. История, этапы и таймеры не сохраняются: после перезагрузки или повторного включения автоматики наблюдение начинается заново, включая страховочный интервал. Время включения до загрузки не считается известным временем физической работы.

Успех сервиса не считается подтверждением реле. Ошибка вызова или отсутствие обратной связи блокирует дальнейшие команды данного процесса и отражается в `last_error` и `commands_blocked`. После исправления причины выключите и снова включите «Автоматика». Автоматических повторов неудачных команд нет.

Доступны атрибуты `phase`, а для влажности — `trend`, `slope`, `peak`, `stable_windows`, `falling_seen`, `sensor_valid`, `restart_inhibited`, `stop_reason`. Пик используется для наблюдения и не является самостоятельным порогом выключения.

## Обслуживание и переход с pyscript

Каждый экземпляр имеет свой сохраняемый переключатель. Его отключение отменяет таймеры и ожидающие действия, но само не переключает оборудование. Уже отправленная команда завершается. У новых процессов нет кнопки короткого нажатия, поскольку их источники — состояния датчиков.

Отключение влажностной автоматики оставляет вентилятор ванной в текущем состоянии. Пока он включён, общая вытяжка продолжает реагировать на его состояние. Для обслуживания общего вентилятора отключайте именно процесс общей вытяжки: другие процессы Home Control его реле не командуют.

Порядок перехода:

1. Обновить файлы интеграции и перезапустить HA.
2. Добавить четыре записи и задать источники и выходы. Новые процессы выключены.
3. Отключить **оба** старых pyscript перед включением новых вентиляторных процессов: прежний скрипт влажности сам командует общим реле.
4. Включить общую вытяжку, затем влажностный процесс и освещение.
5. Проверить свет, запуск общей вытяжки, её выбег и диагностические атрибуты влажности на реальных данных.

Алгоритмы проверяются тестами с имитацией состояний и сервисов, без подключения к реальному оборудованию.
